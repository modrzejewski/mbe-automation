# Many-Body Expansion (MBE) Workflow Assessment Report

This report evaluates the physics validity, mathematical validity, and robustness of the `many-body expansion` module in `mbe-automation`.

## Assessment Summary

| Component/File | Issue Type | Description | Severity | Recommendation |
|---|---|---|---|---|
| `structure/molecule.py` | Mathematical Validity | **Incorrect RMSD scaling for Pymatgen backend.** The `_match_pymatgen` function multiplies the `rmsd` returned by `pymatgen.analysis.molecule_matcher.HungarianOrderMatcher` by `np.sqrt(3.0)`, assuming `pymatgen` flattens the vectors and doesn't normalize by 3. However, `pymatgen` natively returns the correct standard RMSD (incorporating Kabsch optimal alignment and proper division by the number of atoms). Multiplying by `\sqrt{3}` mathematically invalidates the RMSD comparison and results in improperly scaled tolerances. | High | Remove the `np.sqrt(3.0)` multiplication factor in `_match_pymatgen` to align with the correct mathematical formulation of RMSD. |
| `configs/many_body_expansion.py` & `workflows/many_body_expansion.py` | Robustness | **Crash on missing required dependency (Calculator).** The `many_body_expansion.run` workflow hardcodes `match_mode="energy_only"` for `identify_molecules`. This mode intrinsically requires an ASE calculator. However, the `Clusters` config object (in `configs/many_body_expansion.py`) initializes `calculator = None` by default and does not validate its presence in `__post_init__`. If a user runs the default configuration, the code will invariably crash deep in the execution stack. | High | Add a validation check in `Clusters.__post_init__` to explicitly raise a clear configuration error if `calculator` is `None`, or default the `match_mode` to "rmsd_only" if no calculator is supplied. |
| `structure/clusters.py` | Physical Validity (Robustness) | **Missing Supercell Center-of-Mass Alignment in `_supercell_size`.** In `_supercell_size`, the central bounding volume is determined using raw unshifted `atomic_properties` coordinates. However, in `_expand_to_supercell`, the entire coordinate grid is rigidly shifted to the collective center-of-mass (`total_com`) prior to final output. If the input raw unit cell is positioned far from the origin (or has large arbitrary translations), `_supercell_size` will calculate asymmetric or insufficient bounding box limits because it iterates symmetrically `(-n, n)` around the Cartesian origin, not around the raw `total_com`. This can lead to missing interacting boundary molecules. | High | Shift `central_batches` by the true unit cell center of mass inside `_supercell_size` prior to computing distances, or compute fractional shifts relative to the raw structure's centroid. |
| `structure/clusters.py` | Mathematical Validity | **False Positives in Topological Permutations (`fast_compare`).** In `_filter_candidates_by_min_rij`, cluster distance matrices are flattened and sorted row-wise (`np.sort(np.column_stack(min_dists), axis=1)`) to populate `sorted_min_rij`. `ReducibleClusters.fast_compare` uses this sorted 1D array to approximate graph isomorphism. Sorting destroys edge mapping: two clusters with completely different spatial arrangements could share the same sorted array of pairwise distances. This leads to false positives that are correctly, but expensively, discarded by the subsequent exact RMSD match. | Low | No logical bug since exact RMSD catches it, but for massive structure clusters, replacing the sorted distance list with a more rigorous topological invariant (like a Coulomb matrix eigenvalue spectrum or explicit graph matching) would improve efficiency. |
| `structure/clusters.py` | Physical Validity | **Cliques vs Connected Graphs.** The `max_min_rij` cutoff logic in `_filter_candidates_by_min_rij` requires all intermolecular pairs within a cluster to be strictly less than the cutoff. This inherently forces a dense "clique" topology. While mathematically consistent with the code's definitions, physical many-body expansions often evaluate chain-like clusters (where A-B and B-C are close, but A-C is far). This clique restriction physically ignores linear cooperative many-body effects. | Low | Explicitly document that the cluster extraction algorithm strictly filters by complete graph cliques rather than simply connected subgraphs. (Note: The memory acknowledges this as intentional). |
| `mbe/tasks.py` | Mathematical Handling | **Monomer Distance Handling.** `_split_by_distance` successfully splits monomers by capturing `np.isnan(t.characteristic_distance)`. However, `_distance_bins` explicitly throws a ValueError for monomers, pushing the sorting and task division up a level. This design is robust, effectively treating monomers as a mathematically singular tier distinct from pairwise physical distances. | None | The current architectural split between monomer processing and n-mer binning is robust and mathematically sound. |
